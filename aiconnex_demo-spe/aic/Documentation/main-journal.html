DOC-001

AI-CONNEXX OVERVIEW

High-level overview of the AI-CONNEXX machine learning workflow studio for prognostic metrics.

Process Flow Chart

Subsystem Logic

AI-CONNEXX is a Total Automation Solution (TAS) machine learning workflow studio designed for industrial diagnostics, prognostics, and real-time sensor telemetries. At its core, the platform allows industrial engineers—who might not be professional data scientists—to upload multi-table archives and build robust regression or classification prediction services automatically.

By connecting ingestion modules, data profiling nodes, feature engineers, splitters, estimators, validation gateways, and monitoring APIs, the studio builds a seamless pipeline. It translates complex machine learning operations into intuitive, visual drag-and-drop actions.

Source Code Example

# AI-CONNEXX Core Initialization class AIConnexStudio: def __init__(self, run_id: str, workspace_path: str): self.run_id = run_id self.workspace = workspace_path self.manifest = None def bootstrap(self): print(f"[Boot] Starting pipeline workspace for Run ID: {self.run_id}") return True
DOC-002

SYSTEM ARCHITECTURE

Detailed look into the 9 microservices running independently in the studio.

Process Flow Chart

Subsystem Logic

The AI-CONNEXX platform follows a decentralized, microservice-based architecture. Instead of running a single monolithic process, it spreads the processing load across nine independent modules that communicate via REST APIs. This design ensures that if one processing step encounters resources limits, other active nodes remain unaffected.

All microservices are unified under a shared file storage system to exchange compiled CSV outputs and serialized pickle estimators.

List of Core Services:

  • Dataset Profiler (Port 8000): Performs statistical analysis and task classification.
  • DAG Orchestrator (Port 8001): Directs step sequences and manages current run executions.
  • Recipe Orchestrator (Port 8002): Resolves specific DAG definitions to build execution recipes.
  • Data Preparation API (Port 8003): Imputes missing values, encodes categories, and scales columns.
  • Feature Engineering API (Port 8004): Creates rolling window statistics.
  • Split API (Port 8005): Partitions datasets into validation sets.
  • Train API (Port 8006): Fits models in secondary subprocess tasks.
  • Evaluate API (Port 8007): Formulates performance scoring reports.
  • Deploy API (Port 8008): Registers and hosts endpoint model estimators.

Source Code Example

# Microservices Endpoint Definitions SERVICES = { "profiler": "http://127.0.0.1:8000", "dag": "http://127.0.0.1:8001", "recipe": "http://127.0.0.1:8002", "prepare": "http://127.0.0.1:8003", "feature": "http://127.0.0.1:8004", "split": "http://127.0.0.1:8005", "train": "http://127.0.0.1:8006", "evaluate": "http://127.0.0.1:8007", "deploy": "http://127.0.0.1:8008", }
DOC-003

CLOUD ARCHITECTURE

Deployment schema for scale, containers, object stores, and database integrations.

Process Flow Chart

Subsystem Logic

For cloud deployment, AI-CONNEXX services are wrapped inside Docker containers managed by a Kubernetes cluster. A front API Gateway (like Nginx, Traefik, or AWS ALB) routes client calls to individual service containers based on URL paths.

The workspace data is housed inside a Shared Volume (EFS / Ceph PersistentVolumeClaim) so all service instances can quickly access intermediate CSV files. Model pickle objects are backed up to S3 or MinIO object stores for long-term archiving, and state records are logged inside PostgreSQL databases.

Source Code Example

# Kubernetes Deployment Spec Snippet apiVersion: apps/v1 kind: Deployment metadata: name: aiconnex-compiler spec: replicas: 3 template: spec: containers: - name: compiler image: aiconnex/compiler:v1.0 volumeMounts: - mountPath: /workspace name: shared-volume

USER JOURNEY OVERVIEW

Walkthrough of how the user uploads files, runs the pipeline, and tests predictions.

Process Flow Chart

Subsystem Logic

The product is designed to minimize user friction. A standard session follows four visual steps:

  1. Ingest: User drops a dataset (e.g., ZIP or Excel) into the frosted glass Dropzone.

DOC-005

COMPILER

Inner workings of the multi-format Ingestion & Relational Compiler Engine.

Process Flow Chart

Subsystem Logic

The compiler is the foundational layer. It accepts archives of any format, converts them to standard CSV structures, and applies relational joins based on timestamp and group keys. It separates tables into Fact tables (containing primary metrics) and Dimension tables (containing background metadata).

Once aligned, the engine performs left-outer index joins, then verifies that the final row counts are clean using a Cartesian Guard constraint checker.

Source Code Example

# Multi-format extension compiler parser def convert_to_csv(filepath: Path) -> Optional[Path]: ext = filepath.suffix.lower() if ext in (".csv", ".txt"): return filepath csv_path = filepath.with_suffix(".csv") if ext in (".xlsx", ".xls"): pd.read_excel(filepath).to_csv(csv_path, index=False) return csv_path elif ext == ".json": pd.read_json(filepath).to_csv(csv_path, index=False) return csv_path return None
DOC-006

DATASET PROFILER

Computes dataset statistics and automates target family detection.

Process Flow Chart

Subsystem Logic

The Dataset Profiler analyzes compiled CSV files to map columns, determine null ratios, check value ranges, and compute metrics. If no target variable is defined, the system automatically checks column headers for words like RUL, target, or label.

The profiler outputs a diagnostic dictionary containing class distribution balances, column types (numeric vs categorical), and suggested ML families.

Source Code Example

# Profile and detect ML task def detect_task_family(df, target_col): if df[target_col].nunique() <= 10 or df[target_col].dtype == object: return "Classification" else: return "Regression"
DOC-007

DAG

Resolves node connections and directs execution flows.

Process Flow Chart

Subsystem Logic

The Directed Acyclic Graph (DAG) defines how data flows between services. Rather than executing random scripts, each run maps to a strict graph schema. For example, DAG_514 represents a standard regression sequence.

The resolver checks that data preparation completes successfully before calling the feature builder, splitting arrays, fitting estimators, evaluating error metrics, and activating predicting routes.

DOC-009

PREPARE

Details missing values imputation, standard scaling, and one-hot encoding operations.

Process Flow Chart

Subsystem Logic

The Data Preparation node cleans raw tables. To avoid missing value issues in scikit-learn models, the preparation script applies forward-fill (ffill) and backward-fill (bfill) strategies, falling back to column medians where needed.

Additionally, numerical columns are scaled to standard ranges, and categorical labels are transformed using one-hot encoding or index mapping before writing output tables.

Source Code Example

# Imputation & encoding pipeline execution def execute_prepare(input_csv: Path, output_csv: Path): df = pd.read_csv(input_csv) # Forward fill then backward fill df = df.ffill().bfill() df.to_csv(output_csv, index=False) return True
DOC-010

FEATURE ENGINEER

Details rolling statistics generation, lag calculations, and sensor diff variables.

Process Flow Chart

Subsystem Logic

Feature Engineering converts static sensor points into temporal trend inputs. For high-frequency industrial sensors (e.g. SCADA telemetry), the absolute value at a single timestamp has less signal than the direction and variance of that value over time.

The feature builder generates rolling averages, sliding variances, difference signals, and past lag indicators (window sizes: 10, 20 intervals), saving the enriched columns into an engineered.csv file.

Source Code Example

# Rolling mean calculation for sensor columns def compute_rolling_features(df, sensor_cols, window=10): for col in sensor_cols: df[f"{col}_roll_mean"] = df[col].rolling(window=window, min_periods=1).mean() df[f"{col}_roll_std"] = df[col].rolling(window=window, min_periods=1).std().fillna(0) return df
DOC-011

SPLIT, TRAIN & EVALUATE

Splitting logic, fitting models, and generating regression/classification scorecards.

Process Flow Chart

Subsystem Logic

These three backend services run consecutively:

  • Split: Splits data into train and test segments. For temporal datasets, standard random splitting can leak information. The partitioner therefore supports sequential splitting to preserve temporal order.
  • Train: Fits regression (e.g. Ridge Regression, Random Forests) or classification models in independent tasks to avoid main thread timeouts.
  • Evaluate: Generates error scorecards (RMSE, MAE, R2 scores for regression, or Accuracy, Precision, Recall, F1 for classification).

Source Code Example

# Sequential split for time series data def split_sequential(df, test_size=0.2): split_idx = int(len(df) * (1 - test_size)) train = df.iloc[:split_idx] test = df.iloc[split_idx:] return train, test
DOC-012

VALIDATION GATEWAY 1 (VG-1)

Ensures metric quality satisfies accuracy thresholds.

Process Flow Chart

Subsystem Logic

Validation Gateway 1 (VG-1) checks that training metric scores satisfy production standards before model deployment. If the evaluation scorecard reveals low performance, VG-1 blocks the pipeline execution.

The standard gate rules are:

  • For Regression tasks: Coefficient of determination (R2 Score) must be greater than or equal to 0.90.
  • For Classification tasks: F1 Score / accuracy must be greater than or equal to 0.90.

Source Code Example

# Metric Gate validation rules def validate_vg_1(metrics, task_family): if task_family == "Regression": return metrics.get("r2", 0.0) >= 0.90 elif task_family == "Classification": return metrics.get("accuracy", 0.0) >= 0.90 return False
DOC-013

VALIDATION GATEWAY 2 (VG-2)

Measures average inference latency to satisfy millisecond constraints.

Process Flow Chart

Subsystem Logic

Validation Gateway 2 (VG-2) measures model inference latency to ensure real-time suitability. Highly accurate estimators (like deep neural networks) might fail this check if they process slow matrix multiplications.

The gate runs 100 test prediction loops on the deployment server:

  • If the average response time per batch exceeds 50ms, VG-2 blocks deployment to prevent system lag.

Source Code Example

# Latency Gate validation check def validate_vg_2(predict_func, sample_data, max_latency_ms=50.0): import time start = time.time() for _ in range(100): predict_func(sample_data) mean_lat = ((time.time() - start) / 100.0) * 1000 return mean_lat <= max_latency_ms, mean_lat

DOC-015

MONITORING

Tracks prediction latency, resource usage, and data drift over active streams.

Process Flow Chart

Subsystem Logic

The monitoring service runs in the background. It measures CPU/memory usage, requests metrics (QPS), and data drift. If the statistics of incoming SCADA logs drift from the training distribution, the system triggers alerts to prompt model retraining.

Source Code Example

# Check for statistical data drift def compute_data_drift_score(train_df, stream_df, column): # Perform Kolmogorov-Smirnov check to detect distribution shift from scipy.stats import ks_2samp stat, p_value = ks_2samp(train_df[column], stream_df[column]) return p_value < 0.05 # True indicates significant drift

The studio integrates an intelligent AI Data Agent. Rather than navigating menus manually, users can converse with a copilot that writes SQL-like filters, compiles archives, explains validation scorecards, and triggers pipeline executions.

The agent operates within a glass slide-over drawer panel, providing real-time code fixes and pipeline status indicators.
