MONITORING

Document Summary

Tracks prediction latency, resource usage, and data drift over active streams.

1. Data Flow Chart

2. Functional Design & Overview

Located in services/9_deploy_monitor/, the monitoring service tracks API request counts, prediction latency, and system resource metrics.

Additionally, it implements **Data Drift Monitoring** to ensure data distributions match training expectations. The system runs the **Kolmogorov-Smirnov (KS) test** on incoming numeric streams, comparing them to baseline distributions:

$$D = \sup_x |F_{\text{train}}(x) - F_{\text{live}}(x)|$$

If the KS $p$-value falls below a threshold ($0.05$), the system flags data drift, notifying operators that the model should be retrained.

3. Implementation Code Reference

# Drift monitoring using Kolmogorov-Smirnov statistical tests from scipy.stats import ks_2samp import pandas as pd def check_feature_drift(train_df: pd.DataFrame, live_df: pd.DataFrame, threshold=0.05) -> dict: """Compares training and live data distributions to detect drift.""" drift_results = {} # Run test on numeric columns numeric_cols = train_df.select_dtypes(include='number').columns for col in numeric_cols: stat, p_val = ks_2samp(train_df[col], live_df[col]) drift_results[col] = { "ks_statistic": stat, "p_value": p_val, "drift_flag": p_val < threshold } return drift_results
