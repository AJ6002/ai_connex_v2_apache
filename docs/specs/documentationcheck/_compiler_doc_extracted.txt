1. Executive Summary
    
The AI-ConneX Data Studio Compiler is the first machine-processing layer after the AI-ConneX conversational interface.
    
Its purpose is to eliminate one of the largest barriers between industrial data and artificial intelligence:
    
Industrial users should not have to understand data engineering, file formats, schemas, joins, merges, encoding, or data normalization before using AI-ConneX.
    
Industrial data is rarely delivered in a clean, standardized form.
    
A plant may provide:
    
CSV files
    
Excel workbooks
    
JSON
    
XML
    
Parquet
    
TXT/log files
    
database exports
    
ZIP archives
    
multiple files from multiple machines
    
historical files
    
files with different column names
    
files with different timestamps
    
files containing different units
    
datasets containing overlapping records
    
datasets that need to be appended
    
datasets that need to be joined
    
datasets that need to be merged
    
datasets containing metadata and operational measurements together
    
The Compiler receives this heterogeneous input and converts it into a validated AI-ConneX Unified Industrial Dataset representation.
    
The Compiler does not simply convert:
    
Excel → CSV
    
or:
    
ZIP → extracted files
    
Instead, it performs:
    
INGEST   ↓IDENTIFY   ↓INSPECT   ↓PROFILE PRE-CHECK   ↓UNDERSTAND   ↓PLAN   ↓UNZIP / EXTRACT   ↓NORMALIZE   ↓JOIN / APPEND / MERGE   ↓SCHEMA HARMONIZATION   ↓TYPE / TIME / UNIT ALIGNMENT   ↓VALIDATION   ↓PROVENANCE   ↓UNIFIED DATASET   ↓DATA PROFILER
    
The Compiler is assisted by an Agent Helper.
    
The Agent Helper does not directly manipulate production data without controls.
    
Its primary responsibility is:
    
Understand ambiguous industrial datasets and recommend the correct transformation plan.
    
The Compiler then validates and executes the plan deterministically.
    
Therefore the architecture follows:
    
Agent reasons     ↓Compiler validates     ↓Compiler executes     ↓Validator verifies     ↓Profiler receives result
    
This separation is fundamental to the reliability of AI-ConneX.
    
    
    
    
2. Position of the Compiler in AI-ConneX
    
The relevant section of the AI-ConneX architecture is:
    
                         JANE / CHATBOT                              │                              │                              ▼                    ┌───────────────────┐                    │   DATA STUDIO     │                    │                   │                    │     COMPILER      │                    └─────────┬─────────┘                              │                    Unified Industrial                         Dataset                              │                              ▼                    ┌───────────────────┐                    │   DATA PROFILER   │                    └─────────┬─────────┘                              │                              ▼                    Recipe Orchestrator                              │                              ▼                        DAG Assigner
    
The Compiler is therefore the boundary between human/industrial intent and structured machine-readable data.
    
    
    
    
3. Why the Compiler Exists
    
    
3.1 Traditional industrial workflow
    
Without AI-ConneX:
    
Industrialist      ↓Finds data      ↓Calls data engineer      ↓Converts Excel      ↓Unzips files      ↓Checks schemas      ↓Renames columns      ↓Writes Python/Pandas code      ↓Joins datasets      ↓Fixes timestamps      ↓Handles missing values      ↓Exports clean dataset      ↓ML engineer receives dataset
    
This creates several problems.
    
    
Problem 1 — Skill barrier
    
Industrial personnel may understand:
    
machines
    
production
    
maintenance
    
process parameters
    
plant operations
    
but may not understand:
    
Python
    
Pandas
    
SQL
    
schemas
    
ETL
    
joins
    
data types
    
encodings
    
    
    
Problem 2 — Format barrier
    
Industrial data can arrive in arbitrary formats.
    
    
    
Problem 3 — Schema barrier
    
Two datasets may represent the same concept using different names.
    
Example:
    
Machine_IDmachine_idmachineasset_idequipment_no
    
    
    
Problem 4 — Relationship barrier
    
The system must determine whether datasets should be:
    
APPENDEDJOINEDMERGEDLEFT JOINEDAS-OF JOINEDUNIONED
    
    
    
Problem 5 — Time barrier
    
Industrial datasets frequently contain:
    
UTC
    
local time
    
date only
    
timestamp
    
epoch time
    
different timestamp resolutions
    
    
    
Problem 6 — Unit barrier
    
For example:
    
temperature = °Ctemperature = °Fpressure = barpressure = psi
    
A simple schema match is insufficient.
    
    
    
    
    
    
4. Compiler Objective
    
The Compiler has six primary objectives.
    
    
Objective 1 — Format independence
    
Accept heterogeneous industrial file formats.
    
    
    
Objective 2 — Dataset understanding
    
Determine what each file/dataset contains.
    
    
    
Objective 3 — Intelligent composition
    
Determine whether datasets should be:
    
appended
    
joined
    
merged
    
left/right/full joined
    
time-aligned
    
unioned
    
    
    
Objective 4 — Unified representation
    
Convert the resulting dataset into the AI-ConneX canonical representation.
    
    
    
Objective 5 — Validation
    
Prevent incorrect transformations from silently entering ML pipelines.
    
    
    
Objective 6 — Provenance
    
Maintain the lineage of every important transformation.
    
    
    
    
    
5. Compiler Definition
    
The AI-ConneX Compiler can be formally defined as:
    
A schema-aware, provenance-preserving industrial data compilation engine that transforms heterogeneous user-provided datasets into a validated canonical representation suitable for downstream data profiling, feature engineering and machine-learning workflows.
    
It is therefore an ETL/ELT + schema inference + data reasoning + validation engine.

7. Core Architectural Principle
    
The most important rule is:
    
LLM / Agent ≠ Data Executor
    
The Agent Helper should not be trusted to arbitrarily execute transformations.
    
Instead:
    
User Intent    ↓Agent Helper    ↓Transformation Proposal    ↓Compiler Validation    ↓Deterministic Executor    ↓Validation    ↓Output
    
This protects industrial data from uncontrolled agent behavior.
    
    
    
    
8. R&amp;D Phase
    
The R&amp;D process should be divided into the following phases.
    
    
R&amp;D-01 — Input Diversity Study
    
Determine the formats that industrial users are likely to provide.
    
    
Initial target
    
CSVXLSXXLSMJSONXMLTXTLOGPARQUETZIP
    
    
    
Future
    
PDF tablesAvroORCSQLiteSQL dumpsAPI responsesS3 objectsindustrial databasesOPC-UA exportsMQTT data snapshotsSCADA exportsMES exportsERP exports
    
    
    
    
    
    
9. R&amp;D-02 — Format Detection
    
The system should never trust the filename extension alone.
    
For example:
    
machine.csv
    
may actually contain:
    
semicolon-separated data
    
or:
    
UTF-16 encoded data
    
or even malformed binary content.
    
The Compiler therefore performs:
    
filename inspection+MIME detection+magic-byte detection+parser probing
    
The detected type is stored separately from the supplied filename.
    
    
    
    
10. R&amp;D-03 — Archive Research
    
ZIP files are particularly important because industrialists frequently send:
    
plant_data.zip
    
rather than individual files.
    
The Compiler therefore needs:
    
ZIP detection     ↓safe extraction     ↓recursive file discovery     ↓file classification     ↓dataset grouping
    
    
    
    
11. Important ZIP Security Failure
    
A naive implementation might execute:
    
zipfile.extractall(output_directory)
    
without checking archive paths.
    
This can create a Zip Slip/path traversal vulnerability.
    
A malicious archive could contain:
    
../../some_sensitive_file
    
The Compiler must therefore resolve every archive member and verify that the final extraction path remains inside the designated workspace.
    
    
    
    
12. ZIP Bomb Failure
    
Another failure is a compressed archive that is tiny but expands to enormous size.
    
Example:
    
Input ZIP:50 MBExpanded:500 GB
    
Without controls, the server could run out of:
    
disk
    
RAM
    
CPU
    
worker capacity
    
The Compiler must implement:
    
maximum archive sizemaximum uncompressed sizemaximum file countmaximum nesting depthmaximum individual file size
    
    
    
    
13. R&amp;D-04 — Dataset Discovery
    
After files are identified, the Compiler creates a discovery report.
    
Example:
    
{  &quot;dataset_id&quot;: &quot;DS-000184&quot;,  &quot;file&quot;: &quot;machine_data.csv&quot;,  &quot;format&quot;: &quot;csv&quot;,  &quot;encoding&quot;: &quot;utf-8&quot;,  &quot;delimiter&quot;: &quot;,&quot;,  &quot;rows_estimate&quot;: 1845023,  &quot;columns&quot;: 17,  &quot;has_header&quot;: true,  &quot;timestamp_candidates&quot;: [    &quot;timestamp&quot;,    &quot;event_time&quot;  ],  &quot;identifier_candidates&quot;: [    &quot;machine_id&quot;  ]}
    
This is not yet the final Data Profiler output.
    
It is a Compiler discovery artifact.
    
    
    
    
14. R&amp;D-05 — Schema Understanding
    
Suppose the user gives:
    
    
File A
    
machine_idtimestamptemperaturepressure
    
    
    
File B
    
MachineTimeTempPressure
    
A naive system sees different schemas.
    
AI-ConneX must infer:
    
machine_id ←→ Machinetimestamp  ←→ Timetemperature ←→ Temppressure ←→ Pressure
    
The Agent Helper assists in this process.
    
    
    
    
    
15. Schema Matching Strategy
    
Schema matching should use multiple signals.
    
                    Schema Match                         │        ┌────────────────┼─────────────────┐        ▼                ▼                 ▼     Name           Data Type          Values   Similarity        Similarity        Similarity        │                │                 │        └────────────────┼─────────────────┘                         ▼                  Semantic Score
    
Potential scoring:
    
column_name_similarity+datatype_similarity+sample_value_similarity+unit_similarity+semantic_embedding_similarity+timestamp compatibility+domain vocabulary
    
The final result should be a confidence score.
    
    
    
    
16. Agent Helper
    
The Agent Helper is the intelligent reasoning component.
    
It receives:
    
dataset metadata+schemas+sample values+column statistics+user objective+known industrial vocabulary
    
It produces:
    
transformation proposal+confidence+reason+required keys+warnings
    
Example:
    
{  &quot;operation&quot;: &quot;JOIN&quot;,  &quot;left&quot;: &quot;machine_data&quot;,  &quot;right&quot;: &quot;production_data&quot;,  &quot;keys&quot;: [    &quot;machine_id&quot;,    &quot;timestamp&quot;  ],  &quot;join_type&quot;: &quot;LEFT&quot;,  &quot;confidence&quot;: 0.94,  &quot;reason&quot;: &quot;Both datasets share machine identifier and compatible timestamps.&quot;}
    
    
    
    
17. Append Decision
    
The Compiler should prefer APPEND when:
    
schemas are substantially compatibleANDrecords represent different partitions/time periodsANDno complementary-key relationship is required
    
Example:
    
Jan.csvFeb.csvMar.csv
    
becomes:
    
Jan +Feb +Mar ↓APPEND
    
    
    
    
18. Join Decision
    
JOIN is appropriate when datasets contain complementary attributes.
    
Example:
    
Machine:machine_id | timestamp | temperatureProduction:machine_id | timestamp | production_rate
    
Output:
    
machine_idtimestamptemperatureproduction_rate
    
    
    
    
19. Merge Decision
    
MERGE should be used when overlapping datasets require reconciliation.
    
For example:
    
Machine A:machine_id | temperature | pressureMachine B:machine_id | temperature | vibration
    
The Compiler may produce:
    
machine_idtemperaturepressurevibration
    
But if both datasets contain different values for the same field, the conflict must be recorded rather than silently overwritten.
    
    
    
    
20. Join Explosion Failure
    
A major R&amp;D failure mode is an incorrect join.
    
Example:
    
Dataset A:
    
machine_id = M01
    
appears 100,000 times.
    
Dataset B:
    
machine_id = M01
    
appears 50,000 times.
    
Joining only on:
    
machine_id
    
can potentially create billions of combinations.
    
This is a many-to-many join explosion.
    
The Compiler should therefore estimate join cardinality before execution.
    
Expected join size        ↓Risk estimation        ↓If excessive        ↓Reject / require confirmation
    
    
    
    
21. Timestamp Alignment Failure
    
Industrial data may contain:
    
2026-08-14 10:00:00
    
while another dataset contains:
    
14/08/2026 10:00
    
and another:
    
1723636200
    
The Compiler should normalize these into a canonical timestamp representation.
    
Recommended internal representation:
    
UTC timestamp+original timezone+original timestamp
    
Do not discard the original value.
    
    
    
    
22. Timestamp Granularity Failure
    
Consider:
    
Sensor:1-second intervals
    
and:
    
Production:1-hour intervals
    
A normal equality join will fail.
    
The Compiler should detect granularity differences and potentially recommend:
    
AS-OF JOINWINDOW JOINRESAMPLINGAGGREGATION
    
rather than forcing equality.
    
    
    
    
23. Unit Mismatch Failure
    
Example:
    
Dataset A:temperature = °CDataset B:temperature = °F
    
The column names are identical.
    
A purely schema-based Compiler would incorrectly treat them as identical.
    
Therefore the Compiler must consider:
    
semantic meaning+unit+value distribution
    
before combining them.
    
    
    
    
24. Encoding Failure
    
Industrial files may use:
    
UTF-8UTF-8 BOMUTF-16Latin-1Windows-1252
    
The Compiler should attempt safe encoding detection and record:
    
original_encodingdetected_encodingconversion_applied
    
    
    
    
25. CSV Failure
    
CSV is deceptively difficult.
    
Potential problems:
    
,;|\t
    
Different delimiters may be used.
    
Fields may contain:
    
&quot;Machine, Line 1&quot;
    
without being correctly escaped.
    
The Compiler should detect:
    
delimiterquote characterescape characterheaderencodingline ending
    
before parsing.
    
    
    
    
26. Excel Failure
    
Industrial Excel workbooks may contain:
    
multiple sheets
    
hidden sheets
    
merged cells
    
header rows beginning at row 5
    
notes above the table
    
multiple tables on one sheet
    
formulas
    
macros
    
blank rows
    
inconsistent columns
    
The Compiler therefore needs an Excel discovery stage:
    
Workbook   ↓Sheet discovery   ↓Table-region detection   ↓Header detection   ↓Schema extraction
    
    
    
    
27. JSON Failure
    
JSON can represent:
    
array of objects
    
or:
    
nested objects
    
or:
    
deeply nested telemetry
    
Example:
    
{  &quot;machine&quot;: {    &quot;id&quot;: &quot;M01&quot;,    &quot;telemetry&quot;: {      &quot;temperature&quot;: 72.4    }  }}
    
The Compiler needs a controlled flattening strategy.
    
It must not arbitrarily flatten every nested structure because hierarchy can contain meaning.
    
    
    
    
28. XML Failure
    
Industrial systems frequently exchange XML-like structured data.
    
Potential problems:
    
namespaces
    
deeply nested structures
    
malformed XML
    
external entity attacks
    
enormous XML expansion
    
The parser should therefore use secure XML parsing practices.
    
    
    
    
29. Data Type Failure
    
A column may contain:
    
123N/A4
    
The parser may infer it as:
    
string
    
instead of:
    
integer
    
The Compiler should perform type inference with explicit handling of:
    
nullmissingNAN/Aunknown-error
    
    
    
    
30. Duplicate Data Failure
    
Two files may contain overlapping records.
    
Example:
    
January.csvJanuary_backup.csv
    
Appending both creates duplicate records.
    
The Compiler should calculate duplicate signatures using candidate keys such as:
    
machine_id+timestamp+measurement
    
where appropriate.
    
It should distinguish:
    
exact duplicate
    
from:
    
legitimate repeated observation
    
    
    
    
31. Schema Drift
    
Industrial systems evolve.
    
Version 1:
    
temperaturepressure
    
Version 2:
    
temperaturepressurevibration
    
Version 3:
    
temp_cpressure_barvibration_mm_s
    
The Compiler should not treat this as an error automatically.
    
It should detect:
    
schema version change
    
and create a harmonization plan.

33. How AI-ConneX Overcomes Agent Errors
    
The Agent Helper must never be the final authority.
    
Architecture:
    
                AGENT HELPER                     │                     ▼             Proposed Plan                     │                     ▼              PLAN VALIDATOR                     │        ┌────────────┼─────────────┐        ▼            ▼             ▼     Schema       Cardinality     Units     Check          Check         Check        │            │             │        └────────────┼─────────────┘                     ▼              EXECUTION ENGINE                     │                     ▼              RESULT VALIDATOR
    
This provides a safety boundary around the LLM.
    
    
    
    
34. Confidence Policy
    
Recommended policy:
    
Confidence &gt;= 0.90    → automatic execution0.75–0.89    → execution with warning / optional confirmation0.50–0.74    → ask user or perform additional analysis&lt; 0.50    → do not execute
    
For high-risk transformations, confidence alone should not be enough.
    
Example:
    
Potential many-to-many JOIN
    
should require explicit validation even if the Agent reports high confidence.
    
    
    
    
35. Compiler Execution Model
    
The Compiler should transform the Agent’s recommendation into a deterministic recipe.
    
Example:
    
{  &quot;recipe_version&quot;: &quot;1.0&quot;,  &quot;operations&quot;: [    {      &quot;id&quot;: &quot;op01&quot;,      &quot;type&quot;: &quot;UNZIP&quot;,      &quot;input&quot;: &quot;upload_001&quot;    },    {      &quot;id&quot;: &quot;op02&quot;,      &quot;type&quot;: &quot;APPEND&quot;,      &quot;inputs&quot;: [        &quot;machine_01.csv&quot;,        &quot;machine_02.csv&quot;      ]    },    {      &quot;id&quot;: &quot;op03&quot;,      &quot;type&quot;: &quot;JOIN&quot;,      &quot;left&quot;: &quot;op02&quot;,      &quot;right&quot;: &quot;production.xlsx&quot;,      &quot;keys&quot;: [        &quot;machine_id&quot;,        &quot;timestamp&quot;      ],      &quot;join_type&quot;: &quot;LEFT&quot;    }  ]}
    
The recipe becomes the executable specification.
    
    
    
    
36. DAG Generation
    
The Recipe Orchestrator converts the recipe into a DAG.
    
             upload_001                  │                UNZIP                  │       ┌──────────┼──────────┐       ▼          ▼          ▼   machine01  machine02  production       │          │          │       └────┬─────┘          │            ▼                │          APPEND             │            │                │            └───────┬────────┘                    ▼                   JOIN                    │                    ▼              NORMALIZATION                    │                    ▼              VALIDATION
    
This makes the Compiler compatible with the existing Data Studio DAG architecture.
    
    
    
    
37. Unified Industrial Data Model
    
The Compiler should produce a canonical representation rather than merely a CSV.
    
Recommended structure:
    
AI-ConneX Unified Industrial Dataset│├── Dataset Metadata│├── Entity Information│├── Timestamp│├── Measurements│├── Events│├── Operational Variables│├── Labels / Targets│├── Units│├── Data Quality│└── Provenance
    
    
    
    
38. Canonical Metadata
    
Every compiled dataset should have metadata similar to:
    
{  &quot;dataset_id&quot;: &quot;ACX-DS-000001&quot;,  &quot;source_count&quot;: 7,  &quot;compiled_at&quot;: &quot;2026-08-14T10:30:00Z&quot;,  &quot;schema_version&quot;: &quot;1.0&quot;,  &quot;row_count&quot;: 1845023,  &quot;column_count&quot;: 27,  &quot;operations&quot;: [    &quot;UNZIP&quot;,    &quot;APPEND&quot;,    &quot;JOIN&quot;,    &quot;NORMALIZE&quot;  ],  &quot;quality_status&quot;: &quot;PASS&quot;}
    
    
    
    
39. Provenance Model
    
Every transformation should create lineage.
    
Source File    ↓Source Dataset    ↓Operation    ↓Intermediate Dataset    ↓Operation    ↓Unified Dataset
    
Example:
    
{  &quot;operation_id&quot;: &quot;OP-00042&quot;,  &quot;operation&quot;: &quot;JOIN&quot;,  &quot;inputs&quot;: [    &quot;machine_data.csv&quot;,    &quot;production.xlsx&quot;  ],  &quot;keys&quot;: [    &quot;machine_id&quot;,    &quot;timestamp&quot;  ],  &quot;output&quot;: &quot;dataset_stage_03&quot;}

42. Why Polars
    
Polars is recommended for the primary dataframe engine because the Compiler is expected to process potentially large industrial datasets.
    
Its columnar execution model is well suited to:
    
filtering
    
projection
    
joins
    
aggregations
    
transformations
    
lazy execution
    
For extremely large datasets, the Compiler should avoid loading the entire dataset into RAM unnecessarily.
    
    
    
    
43. Why DuckDB
    
DuckDB becomes the SQL execution layer.
    
It is particularly useful for:
    
CSVParquetArrowlarge local datasetsjoinsaggregationsSQL transformations
    
It can complement Polars rather than replacing it.
    
Recommended division:
    
Polars→ dataframe transformationsDuckDB→ analytical SQL / large joins / file queryingPyArrow→ columnar interchange
    
    
    
    
44. Why FastAPI
    
FastAPI exposes Compiler functionality to:
    
Chatbot
    
Data Studio UI
    
internal orchestration
    
future external integrations
    
It also provides OpenAPI-based API documentation.
    
    
    
    
45. Why Pydantic
    
Pydantic should define the contracts between:
    
Chatbot → CompilerCompiler → Agent HelperAgent Helper → CompilerCompiler → Profiler
    
This prevents loosely structured JSON from moving between components.
    
    
    
    
46. Why an Agent Graph
    
The Agent Helper should ideally operate as a bounded state machine:
    
DISCOVER   ↓UNDERSTAND   ↓PROPOSE   ↓VALIDATE   ↓REVISE   ↓FINALIZE
    
This is safer than an unconstrained autonomous agent.

57. Chatbot → Compiler Contract
    
This is one of the most important interfaces in AI-ConneX.
    
The Chatbot should not send an arbitrary natural-language string only.
    
It should send:
    
USER INTENT+INPUT ASSETS+CONTEXT+DOMAIN+OBJECTIVE+CONSTRAINTS
    
Example:
    
{  &quot;request_id&quot;: &quot;REQ-00001&quot;,  &quot;conversation&quot;: {    &quot;conversation_id&quot;: &quot;CONV-1001&quot;,    &quot;turn_id&quot;: 12  },  &quot;intent&quot;: {    &quot;text&quot;: &quot;Combine all the machine data and production records so they can be used for predictive maintenance.&quot;,    &quot;task&quot;: &quot;DATA_PREPARATION&quot;  },  &quot;domain&quot;: {    &quot;name&quot;: &quot;manufacturing&quot;  },  &quot;assets&quot;: [    {      &quot;asset_id&quot;: &quot;A001&quot;,      &quot;name&quot;: &quot;machine_data.zip&quot;,      &quot;location&quot;: &quot;object://uploads/A001&quot;    },    {      &quot;asset_id&quot;: &quot;A002&quot;,      &quot;name&quot;: &quot;production.xlsx&quot;,      &quot;location&quot;: &quot;object://uploads/A002&quot;    }  ],  &quot;constraints&quot;: {    &quot;preserve_original&quot;: true,    &quot;require_provenance&quot;: true  }}

58. What the Compiler Receives From Chatbot
    
The Compiler receives five conceptual inputs:
    
1. User Intent2. Data Assets3. Industrial Context4. Constraints5. Expected Objective
    
Example:
    
User:&quot;Use these files to prepare a dataset for predictive maintenance.&quot;Compiler receives:Intent:predictive maintenance preparationAssets:machine_data.zipmaintenance.xlsxsensor.csvDomain:manufacturingConstraints:preserve original datamaintain lineage
    
    
    
    
59. Compiler → Agent Helper Contract
    
The Compiler gives the Agent Helper a controlled discovery package.
    
{  &quot;job_id&quot;: &quot;JOB-001&quot;,  &quot;assets&quot;: [    {      &quot;asset_id&quot;: &quot;A001&quot;,      &quot;format&quot;: &quot;csv&quot;,      &quot;rows&quot;: 120000,      &quot;columns&quot;: [        {          &quot;name&quot;: &quot;Machine_ID&quot;,          &quot;dtype&quot;: &quot;string&quot;        },        {          &quot;name&quot;: &quot;Time&quot;,          &quot;dtype&quot;: &quot;datetime&quot;        },        {          &quot;name&quot;: &quot;Temp&quot;,          &quot;dtype&quot;: &quot;float&quot;        }      ]    }  ]}
    
The Agent does not need the entire raw dataset.
    
It should generally receive:
    
metadata+schema+statistics+small representative samples
    
This reduces data leakage and LLM cost.
    
    
    
    
60. Agent Helper → Compiler Contract
    
Example:
    
{  &quot;plan_version&quot;: &quot;1.0&quot;,  &quot;confidence&quot;: 0.94,  &quot;operations&quot;: [    {      &quot;id&quot;: &quot;OP01&quot;,      &quot;type&quot;: &quot;UNZIP&quot;,      &quot;input&quot;: &quot;A001&quot;    },    {      &quot;id&quot;: &quot;OP02&quot;,      &quot;type&quot;: &quot;APPEND&quot;,      &quot;inputs&quot;: [        &quot;A001_FILE01&quot;,        &quot;A001_FILE02&quot;,        &quot;A001_FILE03&quot;      ]    },    {      &quot;id&quot;: &quot;OP03&quot;,      &quot;type&quot;: &quot;JOIN&quot;,      &quot;left&quot;: &quot;OP02&quot;,      &quot;right&quot;: &quot;A002&quot;,      &quot;keys&quot;: [        &quot;machine_id&quot;,        &quot;timestamp&quot;      ],      &quot;join_type&quot;: &quot;LEFT&quot;    }  ],  &quot;warnings&quot;: [],  &quot;requires_confirmation&quot;: false}
    
The Compiler validates this before execution.

This is the second most important interface.
    
The Compiler does not simply send:

to the Data Profiler.
    
It should send:

This creates clean separation of responsibilities.

The Compiler should avoid:

for large industrial datasets.
    
Instead use:
    
lazy executionstreamingchunked ingestioncolumn projectionpredicate pushdownParquetDuckDBPolars

Example:
    
SHA-256(file)

This reduces unnecessary processing.

92. The Core Innovation
    
The Compiler’s innovation is not:
    
“We support CSV, Excel and ZIP.”
    
That alone is not innovative.
    
The real AI-ConneX innovation is:
    
The system accepts industrial data in the form in which the industrial user already possesses it, understands relationships between heterogeneous datasets, determines the appropriate transformation strategy with an Agent Helper, validates that strategy deterministically, executes it as a DAG, preserves provenance, and delivers a canonical dataset to downstream AI systems.
    
That is substantially more powerful.

95. Final Architecture Principle
    
The Data Studio Compiler should ultimately implement this principle:
    
                    DON&#39;T ASK THE INDUSTRIALIST                         TO FIX THE DATA.                              ↓                   LET AI-ConneX UNDERSTAND IT.                              ↓                      AGENT HELPER                       REASONS ABOUT IT                              ↓                         COMPILER                     VALIDATES + EXECUTES                              ↓                       UNIFIED DATA                              ↓                       DATA PROFILER                              ↓                         ML STUDIO
    
The Compiler therefore acts as the industrial data translation and compilation boundary of AI-ConneX.
    
Its responsibility ends when the heterogeneous industrial input has become a validated, canonical, provenance-preserving dataset that Data Profiler can consume without needing to understand the original file-format chaos.
    
    
    
    
96. Stage-1 Definition of Done
    
The AI-ConneX Data Studio Compiler Stage-1 is considered complete when the system can take:
    
one or more arbitrary supported industrial data assets
    
and automatically:
    
✓ identify formats✓ safely extract archives✓ inspect datasets✓ discover schemas✓ identify candidate keys✓ identify timestamps✓ identify units✓ detect schema relationships✓ determine append/join/merge requirements✓ use Agent Helper for ambiguous cases✓ validate the proposed plan✓ construct a DAG✓ execute transformations✓ prevent dangerous joins✓ normalize the canonical schema✓ normalize timestamps✓ resolve units where possible✓ detect duplicates✓ preserve source data✓ maintain provenance✓ generate REPORT_1✓ generate unified Parquet✓ generate schema metadata✓ generate lineage metadata✓ provide a clean input contract to Data Profiler
    
The final handoff is:
    
                    COMPILER OUTPUT                         │        ┌────────────────┼────────────────┐        ▼                ▼                ▼   Unified Data       Metadata         Lineage     Parquet             │                │        │                │                │        └────────────────┼────────────────┘                         ▼                 REPORT_1 / QUALITY                         │                         ▼                  DATA PROFILER
    
That is the formal boundary between Data Studio’s Compiler stage and the Data Profiler stage.
